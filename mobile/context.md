# Project Context

Offline-first personal finance + productivity app. Expo / React Native (SDK 57), TypeScript, NativeWind (Tailwind classes on RN), no backend — everything lives on-device.

Keep this file updated when features are added or architecture decisions change, so anyone (human or AI) picking this project back up can get oriented without re-reading the whole codebase.

## Origin

Originally generated by Google AI Studio as a **web app** (Vite + React) even though a React Native app was requested — AI Studio has no RN output target. That web app still exists, untouched, at the repo root (`src/`, `index.html`, `vite.config.ts`) as a reference. This `mobile/` folder is the real, hand-ported Expo/React Native app — a from-scratch port of the web app's logic layer, plus new modules built directly for mobile.

## Architecture

Layered, strict one-way dependency:

```
types/            → plain interfaces, no logic, one file per domain (finance.ts, productivity.ts,
                    documents.ts, goals.ts, debts.ts, notes.ts, settings.ts), barrel-exported via
                    types/index.ts
database/db.ts    → DatabaseEngine: the entire app state is ONE JSON blob in
                    @react-native-async-storage/async-storage (NOT SQLite — see "Data storage" below).
                    In-memory Record<id, Entity> tables, synchronous reads, runTransaction() for
                    writes (clone-snapshot rollback on throw), pub/sub notify on every write.
database/repositories/ → one file per entity, plain object literal (not a class), CRUD functions
                    calling dbEngine.getTables() / dbEngine.runTransaction(). No file I/O, no
                    React, no UI — pure data access. Id convention:
                    `${prefix}_${Date.now()}_${Math.random().toString(36).substring(2,6)}`
services/         → things repos can't do: file I/O (expo-file-system), sharing (expo-sharing),
                    notifications (expo-notifications), search across repos, backups.
components/ui/    → shared primitives every screen composes: Button, Card, Badge, Input, Select,
                    DateField, Modal, IconHelper, Logo, PressableScale, AnimatedBar,
                    AnimatedCurrency, FadeSwap, SegmentedControl, TabBarButton, listMotion.
components/<domain>/ → finance/, productivity/, documents/, security/, settings/, search/ —
                    feature components, one directory per domain.
screens/          → one per bottom tab, composed from the above. Mostly no props beyond what
                    App.tsx threads down (screens read data via useDatabase(), not props).
App.tsx           → owns ALL modal open/close state and cross-cutting selection state
                    (selectedTransaction, selectedTask, ...). Screens fire callback props
                    (onOpenX, onSelectY); App.tsx decides what happens. This is the one file
                    every feature eventually touches, and the only file to be careful about
                    editing concurrently (see "Working with subagents" below).
```

Reused conventions worth matching before inventing something new:
- Money is always an integer `*Minor` field (paise/cents), converted via `toMinorUnits`/`toMajorUnits`/`formatCurrency` in `utils/currency.ts` — never a float.
- Dates are `"YYYY-MM-DD"` strings (`utils/date.ts`), timestamps are full ISO strings.
- A "manager modal" (Accounts, Categories, Budget, Recurring, Goals, Debts) is one component with local `isCreating`/`editingId` state toggling between a list view and an inline create/edit form — not separate screens.
- Destructive actions go through `Alert.alert` with a `style: 'destructive'` confirm button.
- `audioService.playSoftClick()` / `.playSuccessTone()` / `.triggerHaptic(...)` fire on taps/saves/deletes throughout — check an existing modal for the exact moments if adding a new one.
- Lucide icons (`lucide-react-native`) always take explicit `size`/`color` props — never `className` (see gotcha below).

## Visual design system

The app was restyled app-wide from stock Tailwind `zinc` grays to a bold, color-blocked look (bare warm neutrals + four pastel accents, rounded Plus Jakarta Sans display type, a floating pill bottom nav) matching a fitness-app-style reference the user approved. Two token sources, kept in sync **by hand** (no automatic link):
- `tailwind.config.js` → `theme.extend.colors`: `ink` (a 50–950 warm-neutral scale, a 1:1 replacement for `zinc` by shade number), `surface` (`DEFAULT`/`dark`, replaces `bg-white`/`bg-zinc-900` card-background pairs), and four accent triplets `accentPurple`/`accentOrange`/`accentBlue`/`accentPink` (each `bg`/`DEFAULT`/`deep`). Plus `fontFamily.jakarta` / `fontFamily['jakarta-extrabold']`.
- `src/utils/theme.ts` → the same values as raw hex, for the two places NativeWind `className` can't reach: `lucide-react-native` icon `color` props and Reanimated `useAnimatedStyle` interpolations. Exports `ink`, `surface`, `accent`, and helpers `inkText`/`inkMuted`/`inkBorder`/`themeBg`/`themeSurface` that resolve the right light/dark value from a single `isDark` boolean.

**Tiered application, not a blanket restyle:**
- *Tier 1 (everywhere)* — the mechanical neutral-palette swap (`zinc-N`→`ink-N` at the same shade number) plus a `rounded-2xl`→`rounded-3xl` bump on genuine card containers.
- *Tier 2 (dashboard/summary surfaces only)* — flat pastel accent color-blocking: Home's balance hero + "Your day" task/habit/quick-action tiles (`src/components/home/`), and Money's balance hero + account strip (purple) and `BudgetCard`/`SavingsGoalsCard`/`DebtsCard` (orange/purple/pink respectively). These compute a small local palette (`cardBg`/`cardBorder`/`accentText`/`primaryText`/`mutedText`) from `theme.ts` per `isDark`, since the color itself (not just light/dark) has to flip between a pastel tint and a saturated "deep" fill.
- *Tier 3 (stays neutral, deliberately not color-blocked)* — Settings, all manager-modal forms, Productivity's dense lists, Documents, Global Search, and Money's `TransactionList`/`FinanceAnalyticsView` (dense data views, not summary surfaces). Tier 1 only.

**Bottom nav** (`App.tsx` + `TabBarButton.tsx`) is a floating dark pill, absolutely positioned above the safe-area inset — always dark background regardless of app theme (matches the reference, which keeps its nav bar black even in light mode), so `TabBarButton`'s active-tab highlight circle only ever needs to contrast against that one background, not flip across both themes. Screens reserve `paddingBottom: insets.bottom + 76` in `App.tsx`'s content wrapper so nothing sits behind the floating pill.

## Feature inventory

- **Home** — greeting, balance hero card, today's tasks, daily habits, recent transactions, upcoming bills (only shows if any recurring rule has a reminder due soon).
- **Finance** (`MoneyScreen`, 3 segments via `SegmentedControl`):
  - *Ledger* — searchable/filterable transaction list (`TransactionList`), expense/income/transfer forms.
  - *Analytics* — `FinanceAnalyticsView`, period-based spend breakdown.
  - *Budgets & Rules* — stacked cards: `BudgetCard`, "Scheduled & Subscriptions" (→ `RecurringManagerModal`, now with per-rule reminder toggle + days-before, scheduling real notifications), `SavingsGoalsCard` (→ `GoalsManagerModal`), `DebtsCard` (→ `DebtsManagerModal`). Goals/debts are manual trackers (contributions/payments are hand-entered, not tied to real transactions — avoids double-accounting).
- **Productivity** (`ProductivityScreen`, 4 segments): Tasks, Habits, Focus (pomodoro timer), Notes (`NoteEditorModal` — simple title+body, pin-to-top, search).
- **Documents** — its own bottom tab. Pick any file → copied into permanent app storage (`expo-file-system`'s `Paths.document`, not cache) → view/share via the OS share sheet → rename (display name only, not the file) → delete (removes the file, not just the metadata). Deliberately **excluded** from JSON backup/restore and from Settings' "Reset Data" — see "Data storage" below.
- **Settings** — theme, sound/haptics, currency, PIN + biometric lock (`expo-local-authentication`), JSON backup export/import, Money Manager Excel/CSV importer (`moneyManagerImport.ts` — imports a real personal-finance app's export format), factory reset.
- **Global Search** — header search icon → full-screen overlay (`GlobalSearchOverlay`, native `Modal` with `presentationStyle="fullScreen"`, NOT the shared bottom-sheet `Modal`) searching transactions/tasks/habits/documents/notes at once; tapping a result switches tabs and opens the right detail view.

## Data storage — read this before answering "where's my data"

**Not SQLite.** `@react-native-async-storage/async-storage` stores the *entire* database as one JSON string under a single key (`ppf_local_database_v1`). There is no schema to query, no tables to browse with a SQLite tool. To actually inspect the data: Settings → Export JSON Backup — dumps everything as readable indented JSON.

`documents` (the Documents tab) is deliberately **not** part of that backup/restore cycle, and is explicitly preserved across "Reset Data"/"Factory Reset" (see `db.ts`'s `resetAllData`/`resetToFactoryDefaults` — they carry the `documents` table forward instead of wiping it via `getEmptyDatabase()`). Reasoning: a document record without its backing file is worse than no record, and a metadata wipe would silently orphan the real files on disk forever since nothing else would delete them. Every other table (accounts, transactions, tasks, habits, goals, debts, notes, ...) behaves normally — full participant in backup/restore/reset.

## Known gotchas (spend time here before debugging from scratch)

- **A shallow `{ ...tables }` spread does NOT make nested tables reactive.** `db.ts`'s `runTransaction` mutates each table's `Record` in place (`db.documents[id] = doc`), so the CONTENTS change but the `db.documents` object *reference* doesn't. Any `useMemo`/`useCallback` keyed on `db.someTable` (reference-equality check) then silently returns a stale cached value forever, even though the component correctly re-rendered — until something else (like a full remount) forces a fresh computation. This bit Documents (add/rename/delete not showing until you left and came back) and Notes had the identical bug. **Fixed** in `DatabaseContext.tsx` — the subscribe/refresh handlers now spread every table one level deeper (`cloneTables()`), so each one gets a fresh reference on every update. If you add a new table to `DatabaseTables`, add it to `cloneTables()` too, or this bug comes back for that table.
- **Top-level tab switching used to fully unmount/remount each screen** (`{activeTab === 'X' && <XScreen/>}`), which replayed every list row's staggered entrance animation and recomputed every aggregate from scratch on *every* navigation — this was the real source of the "switching tabs feels laggy" complaint, not any single slow operation. **Fixed** in `App.tsx` — screens now mount once on first visit and stay mounted, toggled via `display: activeTab === 'X' ? 'flex' : 'none'` instead of being torn down. Gotcha this created: `ProductivityScreen`'s `initialFocusTask` prop used to reliably re-seed state on every remount; now that it stays mounted, a `useEffect` keyed on the prop is required to pick up a second "Start Focus" tap from Home. Any other screen that assumes "I get freshly mounted every time I'm shown" needs the same treatment — check for `initial*` props seeded only via `useState()`'s initializer before assuming they still work.
- **NativeWind `className` is silently ignored on non-core components** (`LinearGradient`, `BlurView`, etc.) — they're not patched by NativeWind's `cssInterop` unless explicitly registered. Style them with inline `style` instead, or wrap in a plain `View`/`Text` that carries the `className`. Bit us once already (the Home hero card had no rounding/padding until this was caught).
- **Reanimated + NativeWind can't share one element.** An animated component (`Animated.View` with `useAnimatedStyle`) must carry `style` only; put `className` on a separate plain element wrapped around/inside it. Mixing them silently kills the animation (`react-native-css-interop` spreads the animated style object into a plain object, destroying the Reanimated handle). See `src/utils/nativewindInterop.ts` for the full explanation and the `AnimatedPressable` helper.
- **`KeyboardAvoidingView` doesn't work inside RN's `<Modal>` on Android** (the modal's own window isn't resized by `adjustResize`). `ui/Modal.tsx` instead listens to keyboard show/hide events directly and lifts the sheet by the measured keyboard height.
- **A flex item with `align-self: stretch` clamped by `max-width` doesn't get re-centered** — it stays anchored to the start edge, leaving dead space on the other side. This is why `ui/Modal.tsx` computes an explicit numeric width via `useWindowDimensions()` instead of `w-full`/`max-w-*`/`self-stretch` classes.
- **expo-file-system's API is class-based now** (`File`, `Directory`, `Paths` from `'expo-file-system'`) — the old `FileSystem.writeAsStringAsync`/`readAsStringAsync`/`documentDirectory` functions are legacy (`'expo-file-system/legacy'`) and will throw if called from the main import. `File.copy()`/`.move()` are async, `.exists`/`.size` are sync getters.
- **`expo-audio` (not `expo-av`, which is fully removed as of SDK 55)** for sound playback; `createAudioPlayer()` for imperative use outside a component (e.g. inside a plain service class), `useAudioPlayer()` hook otherwise.
- **`npx tsc --noEmit` can intermittently crash with `RangeError: Maximum call stack size exceeded`** on this machine's Node 24 (default V8 stack size), unrelated to any actual type error — it's happened after the project grew larger, not tied to any specific file. If it happens, don't chase it as a real bug: rerun via `node --stack-size=8000 ./node_modules/typescript/lib/tsc.js --noEmit` (note: `NODE_OPTIONS=--stack-size=...` does NOT work here — it breaks `npx`'s own Node install lookup — call `tsc.js` directly with `node --stack-size=...` instead).

## Build & run

```
cd mobile
npm install
npx expo start            # defaults to port 8090 (see package.json) — avoids a local
                           # XAMPP/Apache conflict on the usual 8081 default, don't remove this
```

Release builds go through **EAS cloud build** (no local Android SDK/Java in this environment) — `eas.json` has a `production` profile set to `buildType: "apk"` with `expo-build-properties` configured for R8 minify + resource shrink + `arm64-v8a`/`armeabi-v7a`-only (drops unused emulator architectures). Run `npx eas login` once, then `npx eas build --platform android --profile production`.

## Verification discipline used throughout this project

Since there's no device/simulator in this environment: `npx tsc --noEmit` after every layer, a full `npx expo export --platform web` bundle build (catches runtime-only issues tsc can't), and a headless-browser render check (`msedge --headless --dump-dom` against the Expo web dev server) — often by temporarily forcing a screen's default tab/state open, checking rendered content + zero JS errors, then reverting the override. This substitutes for real device testing but does **not** verify: native file-picker/share-sheet behavior, actual notification delivery, biometric auth, or anything else that only exists on a real device.

## Working with subagents on this codebase

`App.tsx` is the one file nearly every feature eventually needs (modal state, prop threading). When parallelizing feature work across multiple agents, keep `App.tsx` edits serial (one agent/session at a time) — concurrent edits to it is the most likely source of lost work or silent overwrites. The pattern that's worked well: agents build self-contained new files + edit their own screen, explicitly report back the exact new props their screen needs, and a single agent/session wires `App.tsx` last.
